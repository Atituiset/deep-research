第二章：底层架构原理深度剖析

在深入探究各家科技巨头的具体硅片产品线之前，必须厘清支撑当代AI计算的三大核心底层架构范式。计算单元底层数据流的差异，从根本上决定了芯片在处理大规模矩阵乘法（GEMM）、非线性激活函数以及海量数据搬运时的效率上限与应用场景。

2.1 SIMT与GPU架构：极度并行的吞吐量之王

SIMT架构数据流示意图

图形处理器（GPU）原本为图形渲染中海量的像素处理而设计，但其单指令多线程（SIMT）架构极其契合深度学习中的大规模并行张量运算。GPU内部署了数千个算术逻辑单元（ALU），通过庞大复杂的线程块管理并行任务流。当代AI GPU更是引入了高度专用的张量核心（Tensor Cores），针对矩阵乘法进行了极限优化 [2][6][7]。

核心优势
  • 极高的浮点吞吐量（FP16/BF16/FP32）
  • 深不可测的生态壁垒（CUDA体系）
  • 对非规则并行逻辑与前沿训练架构具有无与伦比的通用性
  • 动态调度适应各种计算模式
核心局限
  • 控制逻辑与线程调度消耗大量硅面积与功耗
  • 在纯规则矩阵运算时，每瓦性能不及定制芯片
  • 内存带宽需求极高，功耗居高不下
  • 大规模集群扩展受互连拓扑限制

2.2 脉动阵列（Systolic Array）与TPU架构

脉动阵列(Systolic Array)数据流示意图

张量处理单元（TPU）代表了另一种截然不同的计算哲学：尽可能抛弃冯·诺依曼架构中需要频繁访问外部存储器的低效模式，转而采用脉动阵列（Systolic Array）设计 [2][3]。成千上万的计算节点（PE）被规则地组织成巨大的二维网格阵列。数据如同血液一般在节点间有节奏地流动、完成乘加运算（MAC），并直接传递给下一个相邻节点，而无需回写主内存。

核心优势
  • 数据在阵列内部高度复用，绕过昂贵内存读取
  • 能耗和内存带宽需求大幅压缩
  • 极其适合大规模矩阵相乘密集型任务
  • 为云服务商提供极稳定的超大规模训练/推理算力
核心局限
  • 对非规则计算模式支持笨拙（稀疏GNN等）
  • 灵活性有限，主要依赖宿主CPU协同调度
  • 无法适应颠覆性算子变化的模型架构
  • 缺乏通用编程生态（对比CUDA）

2.3 NPU与空间计算架构：高能效比的端侧推理霸主

NPU空间计算逻辑 vs GPU/TPU架构对比

神经网络处理单元（NPU）专为在功耗极其受限的边缘和端侧环境（如智能手机、AI PC、人形机器人）中加速AI推理而生 [7][9]。NPU摒弃了通用处理器的繁冗指令集，通常采用高度优化的专用神经执行流水线，原生广泛支持超低精度量化计算（如INT8甚至INT4格式）。通过直接映射神经网络拓扑结构至硬件计算单元，NPU实现了高效的空间计算（Spatial Compute）。

NPU的最核心指标并非绝对算力，而是极高的每瓦性能。在执行预训练模型的推理任务时，其能耗比远远优于全功能的CPU和GPU。这使得NPU成为当前AI PC与智能移动设备实现"全天候端侧AI"不可或缺的物理引擎。但其局限性在于高度的专用化，一旦底层网络模型的算子发生颠覆性变化，硬件的固化逻辑便可能无法适应，且NPU几乎不具备模型训练能力。

2.5 Transformer注意力机制对硬件设计的反向约束

当前所有AI芯片架构的设计，本质上都在回答一个共同的问题：如何最高效地执行Transformer模型的注意力（Attention）和多层感知机（MLP）操作？理解Transformer的计算特征，是理解为什么不同架构在某些场景中表现悬殊的关键。

✓ Transformer的计算特征
  • 矩阵乘（MatMul）占 >95% 计算量：Q×K^T、Attention×V、MLP的全连接层——全部是大规模矩阵乘法 → GPU/Tensor Core天然适配
  • 注意力分数计算（Softmax）：逐元素操作，内存带宽密集 → 需要高带宽HBM
  • KV-Cache驻留：推理时需在内存中保留所有历史token的Key/Value矩阵 → 大容量HBM是关键（MI300X 192GB优势所在）
✗ Transformer对硬件的挑战
  • 注意力计算是O(n²)内存密集：序列长度n=128K时，注意力矩阵=128K×128K×2bytes=32GB → 超出任何单卡SRAM → 必须频繁读写HBM → 受内存带宽制约
  • MoE（混合专家模型）的路由稀疏性：每个token仅激活2/8个专家 → GPU的SIMT模型在大规模并行时利用率骤降至30%以下 → 这正是Graphcore IPU的MIMD优势场景
  • 长序列推理的KV-Cache膨胀：1M context窗口的KV-Cache可达数十GB → 传统80GB H100必须分片到多卡 → MI300X的192GB在推理TCO上反超

这些计算特征直接解释了为什么：① NVIDIA持续倍增HBM容量和带宽（B200: 192GB→R100: 288GB HBM4）；② Google TPU 8i专为推理设计了384MB超大片上SRAM（击破KV-Cache内存墙）；③ Groq LPU完全放弃HBM、全用片上SRAM（避免内存带宽瓶颈但限制了模型规模上限）。Transformer不是普通的神经网络——它是一种以内存带宽,而非FLOPS为第一瓶颈的异常计算范式，这从根本上重塑了AI芯片的架构设计空间。

2.6 GPU微架构核心机制 深度

Warp调度与延迟隐藏

NVIDIA GPU的最基本执行单元是Warp——由32个线程组成的最小调度单位。一个SM（Streaming Multiprocessor）内可同时驻留最多64个Warp（2048线程）。GPU的核心调度策略是零开销线程切换：当某个Warp因等待HBM数据而stall时，Warp Scheduler在单周期内切换到另一个就绪Warp，硬件上下文已在寄存器文件中预分配。这种"以线程级并行掩盖内存延迟"的机制是GPU吞吐量优势的底层根源。

关键洞察：共享内存/L1 Cache的大小直接决定了单个SM能同时驻留多少线程Block——从而决定了Warp调度器有多少"隐藏延迟的弹药"。H100将L1+共享内存提升至256KB，正是为了在HBM3延迟(~300 cycles)面前保持更多活跃Warp。

内存合并与Bank Conflict

GPU的全局内存（HBM）访问效率高度依赖内存合并（Memory Coalescing）：一个Warp内32个线程访问的全局内存地址如果落在同一128-byte对齐的内存段内，则只需1次内存事务；如果分散在不同段，则需最多32次事务——有效带宽退化32倍。这是GPU编程中"结构体数组（AoS）vs 数组结构体（SoA）"数据布局选择的硬件根源。

共享内存Bank Conflict：共享内存被划分为32个Bank（每Bank 4 bytes），同一Warp内若多个线程访问同一Bank的不同地址（且不是广播），则发生Bank Conflict——访问被串行化。n-way bank conflict使有效带宽降为1/n。H100扩展了Bank宽度以缓解此问题。

Roofline模型：AI工作负载的性能边界

Roofline模型是评估AI芯片在实际工作负载中性能瓶颈的核心工具。它将芯片性能限制分为两个区域：

  • Memory-Bound区域（低运算密度）：当操作的FLOP/Byte比率（运算密度）低于芯片的"转折点"时，性能受内存带宽限制。典型场景：逐元素操作（ReLU, LayerNorm, Softmax）、小批量推理。
  • Compute-Bound区域（高运算密度）：当运算密度高于转折点时，性能受峰值算力限制。典型场景：大矩阵乘法（MatMul）、大批量训练。
