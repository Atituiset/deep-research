第十章：AMD Instinct — NVIDIA之外的GPU巨头

在NVIDIA占据约80%数据中心GPU市场的阴影之下，AMD正以Instinct系列加速器展开一场持久的技术反击战。从CDNA架构的快速迭代到MI300X在部分推理场景中反超H100，再到牵头发起UALink联盟打破NVLink封闭生态——AMD正在构建一个从芯片架构到互联标准的全方位对抗体系。

10.1 CDNA架构：从RDNA的分离到AI专用化

AMD在2020年做出了一个关键决策——将GPU架构分叉为游戏向的RDNA和计算向的CDNA（Compute DNA）。这一决策使AMD能够为AI工作负载独立优化计算单元和内存系统，而不受图形渲染管线的历史包袱约束。

CDNA3（2023年发布，搭载于MI300X）是该架构的第三次重大迭代：

MI300X 核心技术特征

  • 8x CDNA3计算芯粒 (5nm)：每芯粒38个Compute Unit，总计304 CU / 19,456个流处理器
  • 4x IOD (6nm)：Infinity Fabric互联 + 内存控制器
  • 1530亿晶体管：超过NVIDIA H100的800亿，体现Chiplet方案的面积优势
  • 192GB HBM3：8-Hi堆叠，5.3 TB/s带宽。大容量设计直接瞄准大模型推理的KV-Cache需求
  • 统一内存架构：CPU（EPYC）与GPU共享地址空间，消除显式的Host-to-Device数据搬运

MI300X的192GB HBM3使其在Llama-2 70B等大模型推理任务中显著优于H100（80GB）。由于无需模型分片到多卡，单卡即可容纳全量权重的KV-Cache，延迟降低40-60%，系统总拥有成本（TCO）优势明显。然而在训练场景，NVIDIA B200凭借FP4 9 PFLOPS的算力密度仍然保持绝对优势。

10.2 ROCm 6.0：AMD的软件突围

如果说硬件是肌肉，软件生态就是神经系统。AMD深知CUDA的护城河有多深——400万+开发者，300+加速库，20年的持续投资。ROCm（Radeon Open Compute）是AMD的回应：

ROCm 6.0 关键技术栈

  • HIP（Heterogeneous-compute Interface for Portability）：CUDA到ROCm的源代码翻译层。hipify-perl工具可自动将90%+的CUDA代码转换为HIP代码
  • ROCm Libraries：rocBLAS、rocFFT、MIOpen（对标cuDNN）、RCCL（对标NCCL），覆盖核心算子
  • PyTorch/TensorFlow原生支持：PyTorch 2.0+已内置ROCm后端，torch.cuda到torch.rocm切换成本极低
  • OpenAI Triton：AMD已贡献ROCm后端，使Triton编译的算子可直接在MI300X上运行

ROCm的年度迭代速度令人瞩目——从2020年仅支持几款工作站GPU，到2024年实现对MI300X的全栈优化，AMD在软件上的投入正以前所未有的速度加码。但客观而言，ROCm的算子覆盖度约为CUDA的60%，社区活跃度约为CUDA的8%，追赶之路仍然漫长。

10.3 UALink：打破NVLink的封闭生态

2024年5月，AMD联合Broadcom、Intel、Google、Microsoft、Meta、HPE和Cisco宣布成立Ultra Accelerator Link (UALink) 联盟。这是对NVIDIA封闭式NVLink生态的正面挑战：

UALink联盟成员生态
对比维度NVLink (NVIDIA)UALink (AMD/联盟)
开放程度完全封闭，仅NVIDIA产品开放标准，任何厂商可采纳
目标带宽NVLink 6: 3.6 TB/s (双向)目标200 GB/s (单链路)，多链路聚合可达TB级
物理层专有SerDes基于以太网物理层 (降低成本)
协议栈NVLink + NVSwitchUALink + 标准交换机
