一、 语义坍塌与破局：从文本 RAG 到图谱驱动的 MCP 架构

在 10M+ LoC 的 C/C++ Monorepo 中，基于 Chunking 和 Vector Embedding 的 RAG 彻底失效。宏定义（#define）、模板偏特化以及条件编译（#ifdef）导致文本层面的检索充满“幻觉”。

工程实践：放弃纯文本检索，通过 Model Context Protocol (MCP) 将底层编译器前端（Clangd）和无损语义树（LST）直接暴露给 Agent。

关键技术点解析

  • USR (Unified Symbol Resolution): 利用 Clangd 提取符号全局唯一标识，消除 C++ 命名空间二义性。Agent 的 find_references 动作直接转换为对 USR 的图谱查询。
  • AST vs LST (无损语义树): Clang AST 会丢弃宏展开前的源码格式。为了实现零格式破坏 (Zero-formatting-break) 的代码生成，必须生成 LST，确保生成的 diff 不包含无关排版变动。

四、 大规模上下文治理：KV Cache 与 Prefix Caching 机制

千万行代码即使经过 GraphRAG 过滤，其包含的头文件定义和上下文（Context）也往往超过 100k Tokens。每次 Agent 交互都重新计算注意力机制会导致难以忍受的延迟（TTFT > 30s）。

Monorepo 拓扑缓存树 (Topology-Aware Caching)

基于 Prompt Caching 技术，我们将 C++ 项目的基础设施层（如 boost 包装层、底层网络库、基础宏定义）作为 Prefix 驻留在 GPU KV Cache 中。Agent 仅计算当前 Worker 分配到的 Translation Unit (TU) 增量 Tokens。

五、 Agent 工具链定义与系统级隔离 (MCP & eBPF)

将 Clangd 能力原子化并注册为 MCP Tools。例如 clang_expand_macro 工具，专门用于防止 Agent 在面对深层嵌套宏时产生“逻辑幻觉”。

当 Agent 执行 make 验证代码时，底层启动 gVisor + eBPF (Extended Berkeley Packet Filter) 探针。严格拦截不受信任的 sys_execve 与网络系统调用，仅允许其在专属的 Git Worktree 中读写。

Core Technical Parsing

  • USR (Unified Symbol Resolution): Utilize Clangd to extract globally unique identifiers for symbols, eliminating C++ namespace ambiguity. Agent's find_references translates directly to graph queries using USR.

4. Massive Context Governance: KV Cache & Prefix Caching

Even filtered by GraphRAG, the headers and context of a 10M+ LoC project often exceed 100k Tokens. Recomputing the attention mechanism on every Agent interaction leads to unbearable latency (TTFT > 30s).

Topology-Aware Prompt Caching

Leveraging Prompt Caching, we persist the infrastructure layers of the C++ project (e.g., boost wrappers, low-level networking, base macros) as Prefixes in GPU KV Cache. The Agent only computes the delta Tokens for the Translation Unit (TU) assigned to the current Worker.

5. Agent Toolchain Definition & System Isolation (MCP & eBPF)

Under the hood, we absolutely cannot allow the Agent to blindly execute compilation via bash. This leads to unpredictable states and corrupted environments.

1. MCP (Model Context Protocol) Injection

Clangd capabilities are atomized and registered as MCP Tools. For example, the clang_expand_macro tool is injected to prevent the Agent from hallucinating logic inside deeply nested macros.

{
  "name": "clangd_expand_macro",
  "description": "Resolve hidden macro states.",
  "parameters": { "usr_id": "string" }
}

2. eBPF-driven Sandbox Defense

When the Agent executes make to verify code, the backend spins up gVisor + eBPF (Extended Berkeley Packet Filter) probes. It strictly intercepts untrusted sys_execve and network syscalls, restricting read/write capabilities solely to its assigned Git Worktree.
